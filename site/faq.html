Frequently asked questions.

Short, direct answers. The documentation goes deeper on most of these.

Is this the official yt-dlp project, or affiliated with it?
No. yt-dlp Studio is an independent desktop application that wraps the open-source yt-dlp project and bundles a build of it for convenience. It is a front-end — it does not fork, replace, or claim credit for the download engine itself. All credit for the actual extraction and downloading work belongs to the yt-dlp maintainers and contributors, and this project is not affiliated with or endorsed by them in any way.
Why is the installer unsigned, and should I trust that?
Code signing costs money on an ongoing basis, and this project deliberately doesn't use it. That means Windows SmartScreen will show an unknown-publisher warning the first time you run a new build — expected behaviour for any unsigned installer, not evidence of tampering. Check that you downloaded it from the official GitHub Releases page, and compare the SHA-256 in the release notes if you want to verify the exact bytes. See the download page for the full walkthrough.
Why is the installer so much larger than a typical yt-dlp wrapper?
Because it bundles two compiled binaries most wrappers make you install separately: a full yt-dlp.exe compiled with PyInstaller, and a full ffmpeg build. Both are compiled from pinned source at build time rather than fetched as prebuilt binaries — see building from source. The trade is a bigger download in exchange for genuinely nothing else to install: no Python, no separate ffmpeg, no PATH configuration.
Does the app phone home, or send any telemetry?
No. The application itself makes zero network requests on its own — the only network traffic is what yt-dlp itself generates when you actually start a download, which is expected of a download tool. This isn't just a claim: the smoke test that gates every release specifically asserts the app makes zero network requests, and fails the release if that ever stops being true.
What happens when yt-dlp breaks on a site because the site changed?
The same thing that happens for every yt-dlp user: the upstream project ships a fix, usually within days, sometimes hours. yt-dlp Studio's vendor/yt-dlp submodule tracks yt-dlp's master branch and is advanced on every pull specifically so the bundled binary can pick up those fixes quickly, rather than being frozen against an old release. The next build after upstream's fix carries it.
Are there automated tests? How is a release verified at all?
There is currently no broader automated test suite — a deliberate, stated gap in this release pass, not an oversight (see Phase 5 of the roadmap). What does gate a release is a smoke test: it launches the real built application, asserts that it renders, that all three bundled binaries (the app itself, yt-dlp.exe, and ffmpeg) actually run, and that the app makes zero network requests. A build that fails any of that does not ship.
Is there a release yet? Where do I get it?
Not yet published. See the download page for what will be there once one ships, or build it from source in the meantime — the same scripts a release would use.
Why doesn't the bundled ffmpeg support x264 encoding?
Because the ffmpeg build is compiled as LGPL-only — --enable-gpl is never passed and --enable-nonfree never will be — so the GPL-licensed libx264 encoder isn't compiled in. Muxing, remuxing, format conversion and audio extraction (most of what yt-dlp Studio actually uses ffmpeg for) are unaffected. See the licensing explanation on the building page.
Will there be a macOS or Linux build?
The project's current, deliberate delivery scope is Windows only. That may change later, but it isn't a current commitment and isn't on the roadmap as it stands today.
